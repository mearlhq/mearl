# 本机 preset 安装宿主

[简体中文](preset-installation.md) | [English](preset-installation.en.md)

`@mearl/setup` 提供本机 preset 资源、Node 激活、兼容扩展的浏览器同步，以及声明的 Skills/Provider 安装与状态核验。欢迎页支持独立浏览器安装；已有兼容本机服务时，同一网页入口可安装整套能力并按实际状态重试。整套生产发行仍待验收；命令将尚未确认的组件报告为 pending，不表示全部能力已经可用。

```bash
npx @mearl/setup preset apply https://example.com/presets/team.json
npx @mearl/setup preset apply ./preset.json
npx @mearl/setup preset update
npx @mearl/setup preset status
npx @mearl/setup preset repair
npx @mearl/setup preset repair --replace-skill example-skill
```

输出为 JSON。退出码 `0` 表示当前所需组件均已确认，`3` 表示已保存的期望状态仍有待安装/同步的组件，`1` 表示失败，`2` 表示命令参数错误。状态检查不下载资源、执行工厂、启动或安装 Native Host。已打开宿主通过现有本机 Socket 通信，不访问云端或自动发现其他设备。

`preset repair` 捕获当前安装 revision，并复用 GUI 的 `resume`、权限同步及组件安装流程，从已接受的本地资源继续安装，不重新解析远端 preset。可重复使用 `--replace-skill <name>` 明确授权本次替换名单中的 Skill 来源或冲突插件注册。名单必须唯一、属于当前启用的 Skill 声明，且在任何宿主重载或组件安装前校验；缺少安装或选择期间发生变更时停止。不带名单的普通修复及后续调用不继承覆盖授权。

## 确切记录与切换

默认目录为 `~/.mearl/capabilities`，显式 `MEARL_CAPABILITY_DIR` 覆盖与 Native Host 一致。包字节按 SHA-256 保存为 `blobs/<sha>.bin`，选定 Node 入口通过硬链接进入 `objects/<sha>.cjs`。不可变 `installations/<revision>.json` 保存确切继承图、包清单、浏览器投影 revision、Node revision、托管模块归属和用户覆盖。

所有资源、图、版本、摘要、Node hook 和配额通过验证后才写入。`active-node.json` 在原 Node 快照上附加 `installationRevision`，以一次原子 rename 同时选择 Node 模块与安装记录。原始 Node 快照及其 revision 不包含安装元数据，仍可独立验证。旧的无安装记录 Node 选择继续可读。

提交按当前选择比较并交换；准备期间被另一进程切换时拒绝，不覆盖新选择。用户独立 Node 模块和 hook 保留，冲突在写入前拒绝；插件和 Provider 的独立注册不参与此处清理。托管资源字节缺失或损坏时，可从确切来源重装修复；指针或安装记录损坏会明确拒绝。相同版本重装不覆盖上一回滚记录。资源准备与提交前支持取消，提交后的同步按实际结果接续。

Node 选择元数据限制 256 KiB，用户覆盖 256 KiB，完整安装记录 16 MiB；包资源维持共享 64 MiB 限制。回收保留当前及上一可回滚选择的资源，未引用的 blob、代码和记录按显式清理回收。旧代码在运行中已捕获到函数和文档，不依赖回收后的文件。

## 默认值与显式覆盖

包与继承来源是清单 URL；Skills 和 Providers 的 `source` 保留安装器语义，例如仓库简写、SSH Git、带 `#ref` 的 Git URL 或 npm 包标识。显式 `./`、`../`、绝对路径 URL 和 HTTP(S)/file URL 相对声明它的 preset 解析，Git ref 不会被移除。`version` 是实际安装版本的兼容范围，不转换为 Git 分支或标签。

`PresetInstaller.configure(overrides)` 替换独立的用户覆盖对象；`{}` 恢复 preset 默认值。生效配置为核心宿主默认值之上的 `preset.defaults → overrides`，对象递归合并，数组、标量和 null 替换。即使用户值与旧默认值相同，更新也保留用户意图，不通过数值比较猜测归属。

能力模块的默认配置放在 `defaults.capabilities`，按模块 ID 深继承；浏览器与 Node 工厂从同一安装快照读取。例如 `"defaults": { "capabilities": { "company-skills": { "manager": "custom" } } }`。配置含义由对应能力包定义。

Skill 管理使用一个 preset 选择的 `skills.manager` Node hook；未提供时使用标准 `skills`。同一个管理器处理全部来源并沿用其已有锁文件，宿主负责禁用状态与插件注册。浏览目录可由同包的 `skills.catalog` 浏览器 hook 提供，二者读取同一默认配置。安装请求可带 `expectedManagerId`，在任何 CLI 或文件修改前核对已捕获的管理器；配置切换时拒绝旧目录操作，不将来源重新解释后自动重试。旧调用者可省略此断言。

管理器的可选 `installBatch` 接受同一来源的多个 Skill，省略 Agent 时使用工具原有自动检测。宿主的 `capture()` 固定后续操作采用的管理器，`installGlobals(source, names)` 一次安装同源列表并保留禁用状态、逐项注册插件、清理同目录的旧注册别名。旧后端没有批次入口时明确要求更新 preset，不向必填 Agent 的旧单项入口传入空值。原界面单项安装合同保持不变。

`preset apply/update` 在包激活后由一个本机宿主安装外部组件。Chrome 关闭时也可自动启动本机服务。宿主核对确切安装 revision 与已接受的 Node revision，固定管理器，按依赖顺序执行；只合并连续且互不依赖的同源 Skill，最多每批 256 项。相同来源和兼容版本已安装时跳过 CLI，插件缺注册时只补注册。Skills 来源不明、同名不同来源或清单冲突会在批次副作用前拒绝，不覆盖用户已有文件。

实际就绪依据包括 Skills 工具已有锁文件、启用或禁用的清单身份/版本、插件与工具箱资源注册，以及 Provider 的真实 package.json、入口文件与注册信息。明确 Git ref 必须匹配；不把锁中的非空 ref 猜作默认分支。Provider source 中的 semver target 和 `version` 范围同时生效；dist-tag 需要 `version` 给出可离线核验的兼容范围。版本范围不会转换成 Git 分支。检查与状态查询不运行更新器、不访问来源网络。

同用户的 preset 批次共用全局安装租约，不因 capability 目录不同而重复执行。宿主跟踪通过其命令服务启动的安装进程；命令超时会终止进程树并等待退出，宿主中断后仍存活的已记录进程会阻止新批次写入。失败保留已完成的外部副作用，重试重新核验实际状态；执行中的一个安装操作可能完成，选择变化后停止后续组件。该租约用于 preset 安装批次，不将所有用户手动修改变成全局原子事务。

安装页为 Skill 来源冲突及尚未完成的插件注册提供“覆盖并修复…”操作，列出待处理的 Skill 和当前能力配置地址。再次确认后，仅为本次重试传递 `replaceSkills` 名单，扩展核对名单仍属于当前安装的待完成项，Native 仅允许在相同 revision 的 `resume` 中使用。安装器与已捕获的 Skill 管理器共同限制覆盖范围：来源冲突项重装文件并保留禁用状态，已安装且仅缺注册的项只修复注册；明确列出的 Skill 可替换其同名工具指向其他目录的旧注册，其他用户别名保留。目录声明的工具别名冲突在安装任何组件前检查，缺失 Skill 的同名旧注册也会提前显示为 `SKILL_PLUGIN_REGISTRATION_CONFLICT`。未确认来源、清单身份、Provider 冲突及选择变更仍会阻止安装。状态刷新、普通重试与自动更新均不携带覆盖授权，授权也不写入安装记录。

能力配置只有一个用户覆盖入口：`apply(source, { overrides: { capabilities: { packageId: config } } })` 或 `configure(overrides)`。执行时按包的 `defaults`、`preset.defaults.capabilities`、用户 `overrides.capabilities` 合并；不再保存独立 `nodeConfig`。默认值不写入用户覆盖，模块停用再启用仍保留用户选择；`configure({})` 清除全部覆盖。代码、有效配置和 hook 未变化时，仅更新安装身份，不重新执行工厂。浏览器和 Node 使用同一配置链，并分别确认激活。详见 [能力包模型](capability-model.md)。

扩展消费 `defaults.simulation.app` 和 `deviceSelection`，与同一安装的 `overrides` 合并后，补齐原快捷设置尚未保存的 App/设备选择。已存全局与标签偏好优先，默认值不写成用户偏好，更新不会切换活动文档。设备使用原有预设、方向、适应窗口和外壳字段；分屏由文档内显式开启。已知非法值在激活前拒绝，尚未实现的设置继续令 `settingsReady` 为 false；其他尚未支持的设置仍按实际消费情况确认。

## 激活确认与失败

安装器向每个已登记本机宿主请求结构化 reload，核对 Node 与安装 revision。断线或旧版本不支持回执时保留安装并显示待同步。工厂明确拒绝新选择时，以 CAS 恢复前一选择并通知所有宿主；在途函数继续保留原实现。相同安装的同步失败仅报告拒绝，不执行历史回滚。

冷宿主加载坏候选时，可从匹配回滚记录恢复已校验的旧选择，同时报告候选错误。如果其他宿主已经完成回滚并删除回滚记录，则有界加载当前确切选择。停用最后一个 Node 包也需要宿主确认，不能因组件列表为空就报告就绪。

安装要求扩展确认时，未确认的浏览器包显示 `BROWSER_SYNC_REQUIRED`，已确认资源但设置尚未应用时显示 `SETTINGS_APPLY_REQUIRED`。未安装的 Skills/Provider 显示对应的安装、版本或注册原因。组件宿主不可用时显示 `INSTALL_REQUIRED` 并附带诊断。其他 Node 执行宿主没有匹配入口时显示 `NODE_HOST_NOT_SUPPORTED`。跨浏览器、本机进程和 npm/Skills 等外部安装不构成全局原子事务。

## 浏览器接收同一批资源

Node 激活通过后，setup 经本机 IPC 向每个宿主请求浏览器同步。扩展通过 Native Messaging RPC 拉取本机已接受的浏览器投影。投影不含 Node-only 包；双端包保留完整资源以校验 bundle revision。同步使用已接受的字节，不再次下载来源或执行 Node 工厂。

宿主一次只保存一个传输会话，空闲 120 秒失效；头部限制 16 MiB，浏览器资源合计限制 64 MiB。资源按摘要寻址、每块原始字节 128 KiB，base64 响应低于 Native Messaging 的一 MiB 消息上限。接收端在分配资源前预检声明配额，校验每份字节、完整浏览器图与包 revision，再由扩展校验 App 定义和页面代码引用。提交前再次确认本机安装身份；损坏、取消或过期不替换原浏览器选择。

浏览器包、确切图、安装身份、用户覆盖和独立 CAS token 在同一 IndexedDB 事务写入。CAS 同时保护浏览器图、包 revision 与安装 token，因此仅配置或 Node 侧变化、浏览器投影相同，也不能覆盖较新的选择。关联内容损坏可保留 token，从确切资源重试修复。自动同步拒绝接管同 ID 的独立包；退出旧 preset 的托管包会清理，独立包与活动文档固定的旧页面代码保留。无关独立包的错误保留诊断，不阻断所选图的确认。

浏览器明确拒绝时保留本机期望选择供重试，各浏览器仍保留其原可用快照；已经接受的其他宿主不进行假定全局原子的回滚，状态不会报告整套就绪。宿主或扩展重启时重新核对实际状态；首次 Node-only 安装不触碰浏览器独立 preset，移除最后一个浏览器包则继续要求空投影的撤销确认。扩展已保存的确切资源和页面代码可在无 Native Host 时恢复，浏览器独立来源安装也继续可用。


Skills 管理沿用现有安装、检查更新、更新和卸载操作。宿主默认使用标准 Skills CLI；已安装能力可通过 `skills.manager` 提供替代管理后端，管理器选择由该能力包的配置控制，所有来源统一交给所选工具。目录、禁用状态与插件/工具箱注册仍由宿主维护。切换只影响后续操作，已接受的操作固定原实现；不改写第三方工具已有锁文件。默认管理器遇到不支持的来源类型会要求启用相应 preset，避免把其他平台的仓库简写解释成 GitHub。

浏览器可调用实现的 revision 同时包含代码与配置，纯配置更新也会使旧 provider 身份失效。已打开的文档实例保留接受时的完整配置；视图资源仍用 bundle revision 校验代码归属。配置更新不要求发布另一个扩展。

## 一条 setup 命令与网页引导

首次安装可在原环境安装命令上选择 preset：

```bash
npx @mearl/setup --preset https://example.com/presets/team.json
```

命令先准备环境包及本机宿主，再在任何 Skill 操作前执行同一 `preset apply`。基础 Mearl Skill 使用该 preset 选定的管理器；若 preset 已托管同名 Skill，则核对其真实状态并保留声明的来源/ref。环境包失败不会应用 preset，preset 准备失败不会转用公共工具。结束时重新查询实际 preset 状态及确切安装身份，不能用先前的就绪结果覆盖期间的变化。

部署用的 `installation.json` 可在 `guide` 之外声明 `presets`，每项只有展示名称、HTTPS preset 清单地址和所需 Chrome 站点范围。范围允许明确的 HTTP、HTTPS 与 `*` 协议以及子域通配，不能声明全站权限；清单来源自身也计入最多 64 项范围。目录限制 32 套配置、64 KiB，不包含安装脚本、CLI 参数或任意命令。

公共 `bridge.html` 嵌在已配置引导页的直接子 frame，`connect.html` 提供同站独立连接页。手动安装时，引导只能选择已登记的 preset ID 和主题，真实按钮在公共 frame 中。扩展核对实际 frame、活动 document 和引导页路径，并自行从固定公共地址读取同一目录。

已配置的引导页可以通过安装桥为当前选择发起首次安装。扩展检查浏览器和已连接本机宿主的选择记录，两者均无 preset 时才打开安装页。已有配置时，引导页保留手动更新和切换入口。

扩展打开自己的安装页。已有权限时直接准备，否则在该页按钮的前台点击中请求 Chrome 站点授权，并记录原有 Agent 域授权。Chrome 保留目录的协议范围，Agent 沿用宿主的域名合同。资源下载还核对 HTTPS、目录协议/主机范围及当前 Chrome 权限，沿用宿主 Cookie 注入，禁止重定向并限制整批 120 秒；资源、图、摘要、App、UI 和运行时配置验证后才替换当前选择，提交前重查目录及授权。

安装会话保存于浏览器 session storage，15 分钟有效，最多 16 项，只允许分配的顶层扩展安装页使用。接受时固定浏览器图、所有包 revision 和安装 token；准备期间变化则拒绝覆盖。完成后的刷新只查询状态，后续选择另一 preset 不会被旧页面重新安装；主动从引导再次点击才接受新的安装选择。页面恢复会重新绑定引导通信，不重复累加选项。

本机 setup 在替换包前保留已有本机 preset。`PresetInstaller.stage` 下载、验证并保存确切资源和期望选择，不调用宿主；其返回的 `activate` 仅允许执行一次，在新运行时初始化后沿原同步/回滚合同激活。后续重试使用 `resume(revision)`，不执行历史回滚。保存的安装记录同时承担部分升级后的恢复标识，不依赖包升级后的版本号；源关闭后仍可恢复同一资源。显式来源可重新准备损坏资源，既有选择并发变化时拒绝陈旧操作。`extension --full` 在替换扩展前执行同一资源准备，卸载不准备或安装 preset。

浏览器独立安装与持久化能力不需要 Native Host。界面单独报告浏览器就绪；preset 包含本机组件时提供上述完整 setup 命令，不将声明数量当作组件实际就绪。已有 Native 安装的同一浏览器投影更新保留安装关联和用户 overrides；投影有变化或关联损坏时保留旧记录并提示使用 setup 一并同步，不能清空覆盖后按默认值启用。已有兼容本机服务时使用下面的网页整套安装流程。

## 主动 setup 沿用浏览器选择

本机首次安装或人工更新时，显式 `--preset` 优先，其次恢复本机已有选择。未选本机 preset 时，完成运行时初始化后、任何 Skill 安装前只读查询已连接的本机扩展。没有已连接扩展时，setup 立即继续本机安装。

已连接浏览器只有一组相同 ID 与来源时，核对部署目录的完整 ID/URL 匹配，资源及继承来源限定为目录中的 HTTPS 范围，声明域名不得扩大。准备完成后再次核对目录和各浏览器选择，提交还要求本机保持未选择状态；变化或冲突不覆盖。已连接但状态不可读、来源不受信或多个浏览器选择不同，明确失败并提示 `--preset <source>`。缺少 Chrome 或 Agent 域权限时，setup 会在扩展状态中报告。

本机环境变量 `MEARL_SETUP_DEFAULT_PRESET` 设置清单来源默认值，仅在显式来源、本机选择和受信浏览器选择均缺失时生效。setup 激活本机 preset 组件，并仅向已连接的扩展同步浏览器资源。CLI 就绪状态与退出码以本机组件为准。已连接扩展的结果显示在 `browsers` 中，同步被拒绝时也会出现在 `warnings` 中。网页整套安装要求扩展确认。普通 Native Host 连接和无人值守更新不会首次采用浏览器 preset。

## 已有本机服务的网页整套安装

扩展在接受安装时，用合计 1.5 秒的握手与只读检查确认本机协议及当前选择。缺失、旧版或暂时不可连接的服务保留独立浏览器安装和 setup 引导；已知安装记录损坏则明确报错。网页不提供本机命令：仅扩展后台能调用整套安装 RPC，Socket 和普通扩展页面路由均拒绝该入口。

本机安装器复用同一 preset 协调器，通过当前扩展会话读取资源，沿用浏览器登录态和授权。每个来源在同次安装中只读取一次，资源按 128 KiB 分块传递并校验长度和摘要；单资源不超过 16 MiB，所有请求预留预算合计不超过 80 MiB。Node 接受确切图后，浏览器从本机接受的同批字节同步，避免两端读到变化的来源。

准备结束、提交前重新核对目录、权限和两端接受时的选择。浏览器同步后只捕获关联于本次安装 revision 的快照，另一安装不能被旧会话当作自己的结果。首次 Node-only 安装保留独立浏览器选择；仅核心浏览器默认值仍需要浏览器确认。

Node 提交后若浏览器同步失败，同页保留确切安装身份并允许恢复；恢复校验本地字节，不重新下载来源。外部组件部分失败时显示待完成并提供显式重试，已就绪项目按真实状态跳过。完成后的刷新只读，不执行安装。界面分别确认浏览器与本机状态，全部确认才显示整套就绪；本机暂时断连时保留已知能力范围和 setup 引导，其他页面更换本机安装后拒绝旧会话恢复。

## 安装 CLI 与管理器一致性

`setup plugin install/uninstall`、已有环境的 Mearl Skill 安装/更新/卸载，以及 `setup --preset` 首次安装，共用已安装的 `skills.manager` 选择。安装 CLI 在本进程捕获管理器，保留原参数、终端 stdin、输出和退出码；不通过 Native RPC 转发交互。原始 CLI 保留调用方的超时设置，手动插件安装没有新增两分钟限制。Agent 与 preset 批次仍沿用其原有有界执行。

本机能力仓库可按明确的 hook 集合加载所需模块，仍校验完整 Node 选择身份、目标字节与提交 guard；安装 CLI 只加载 `skills.manager` 所属模块，不启动其他浏览器/Provider 工厂，也不把局部加载当作整套能力激活回执。损坏或旧版管理器缺少 CLI 入口时明确要求修复 preset，不静默使用另一工具。一次操作保留已捕获实现，下一次操作再读取新选择。

preset 托管的基础 Mearl Skill 不能被普通环境安装覆盖回默认来源。CLI 与 Agent 共用来源/ref、清单身份、版本、禁用冲突及插件注册核验；仅有声明或缺失文件不算就绪，普通 setup/update 会提示通过 preset 修复并报告未完成。未被 preset 托管的基础 Skill 保持原公共来源及安装/核验流程。

Native 批次安装或修复新插件注册时使用 setup 托管归属，供既有更新与卸载流程维护。已有同名、同目录的用户注册保留原归属；preset 修复需要替换其他用户别名时会报告冲突。Agent 刷新或插件导出改名保持托管归属，并保留同目录的用户别名；托管卸载遇到共用目录的用户别名时保留 Skill 文件。

## 按需插件目录

能力包可用 `plugins.catalog` Node hook 返回原命令别名及 `{ description, skill, setup? }` 元数据。宿主只接受当前 preset 已声明的 Skill，过滤停用项，并从继承解析后的声明生成安装参数；子 preset 覆盖来源后无需另写目录。目录在声明组件安装核验后发布，绑定确切 `active-node.json` 内容与安装 revision；更换选择后旧目录读取即失效。只读状态检查不发布或重装目录，全部别名注册也参与整套就绪确认。

按需补装复用 `setup plugin ensure`、当前管理器和原有插件注册流程，与 preset 批次共用同用户的安装租约。安装前拒绝来源冲突，安装后通过工具已有锁记录核对来源/ref、清单身份和声明版本，确认唯一安装路径和命令别名后才注册。目录或选择在安装期间变化时保留已完成文件并拒绝旧请求注册，不执行后续插件命令。失败或超时的命令退出后可重试，已注册插件及用户自行维护的入口不会被目录失效自动删除。

## 声明域名与界面内容

preset 的 `permissions.origins` 声明该配置所需的明确 HTTP/HTTPS 主机范围，继承时取并集，最多 64 项，不接受全站通配。声明本身不会授予权限。CLI 同步后若 Chrome 站点权限或 Agent 域名授权尚缺，安装保持 pending，并提示打开扩展设置中的“授权 preset 域名”；一次点击完成 Chrome 请求及后台域名登记。网页安装仍沿用原有授权步骤。撤权后重新查询状态会恢复 pending。

`defaults.extension.messages` 可按现有消息 key 提供 `{ en, zh_CN? }`，随 preset 继承覆盖，保留原来的参数替换规则。`defaults.extension.rulePresets` 按 ID 提供 `{ name, description: { en, zh_CN? }, rules }`，其中 `rules` 为既有规则编辑器表单。模板只填入编辑器，保存、应用和域名授权仍走原有流程。切换或卸载 preset 会刷新所选字典与模板，已保存的用户规则保留。

## 受信 preset 自动更新

扩展启动后检查当前已安装的 preset，成功后每 12 小时检查一次；下载、同步失败或缺少权限时 1 小时后重试。Chrome alarm 与本地检查时间共同约束频率，Service Worker 重启不会重复下载。浏览器离线或资源、继承、版本/API、贡献校验失败时保留已接受的快照，查询目录和普通页面操作不需要等待更新。没有已安装 preset 时不自动选择或安装目录推荐项。

信任由固定安装站点的 `installation.json` 决定，必须同时匹配已安装 Preset ID 与完整来源 URL。继承清单、包清单与资源的 HTTPS 来源受目录站点范围约束；自动流程拒绝新的本地来源、重定向和 URL 凭据。来源从目录删除或更换时停止自动更新；CLI 显式 apply/update 由调用者选择来源。

新版本需要的 Chrome 站点权限或 Agent 域授权不齐全时，提交与本机代码执行之前停止更新，保留原能力，并只打开一次后台扩展授权页。权限请求由该页用户点击发起；授权后恢复更新。自动更新不会授予权限，也不会因为 Native Host 上线就把浏览器独立安装升级为整套本机安装。

扩展连接时由浏览器安装协调器更新浏览器及其关联的 Node 选择，下载使用既有受控请求链路。整套更新在写入 Node 指针前预检相同资源批次的浏览器贡献和权限。独立浏览器 preset 与另一个 Node-only preset 可以并存；Node-only 的更新保持独立，不覆盖浏览器选择。

Native/CDP 宿主启动 30 秒后检查，后续每小时唤醒并遵守相同的 12 小时/1 小时间隔；它不会为了检查而保活进程。跨进程状态避免多个宿主重复执行同一次检查；浏览器已协调同一选择时让出。无扩展时若更新扩大浏览器权限或增加浏览器运行位置，会延后处理，连接扩展或显式执行 preset update 后完成。

自动更新复用确切安装记录、来源校验、用户 overrides 与冲突检查。相同内容不重新激活工厂；更新保留用户覆盖和独立组件。当前页面继续使用已接受的定义与代码，后续导航/刷新按既有 App 定义刷新策略使用新版，显式锁定定义继续固定。两端同步暂时失败时保留已完成的安装记录并报告 pending，后续检查重试，不将部分就绪标记为整套成功。


## 部署信任目录

受信 preset 目录由部署者维护，核心默认使用空目录。网站构建通过 `MEARL_INSTALLATION_CONFIG_FILE` 注入 JSON；发布 Action 从 `MEARL_INSTALLATION_CONFIG` secret 读取同一份配置。第三方发现目录不能直接用作自动安装目录。preset 自身不能声明其可信；受信安装与自动更新只接受目录中匹配 ID 和完整来源的条目。

默认安装站点、扩展 ID 和本机默认目录 URL 共用 `@mearl/preset/installation-site.json`。本机 setup 与 Native 自动更新均支持 `MEARL_INSTALLATION_CONFIG_URL`，此本机环境变量不接受网页覆盖，也不改变浏览器的固定信任根。自动更新只接受 HTTPS；显式 CLI 迁移的本地验证允许回环 HTTP。部署输出的 `installation.json` 可被读取，配置中只能放可公开读取的地址与策略，不能放凭据。


## 官网直接安装

官网可通过已注入的内容脚本查询扩展版本，然后发送已知 preset ID 的状态或打开请求。版本探测只返回版本信息，不连接 Native Host、不读取目录、不触发安装。网页按钮打开扩展自己的安装视图，由原权限和安装流程执行。

独立部署可在扩展构建时使用 `MEARL_INSTALLATION_CONFIG_URL` 指定受信 HTTPS 目录；构建同时为目录所在站点准备内容脚本与主机权限。目录中的 `guide.url` 指定允许发起安装的完整官网页面路径。宿主核对扩展自身的内容脚本、顶层 frame、当前文档身份与目录来源；网页、URL hash 和消息参数不能修改该信任配置。

已注入内容脚本的 HTTPS 页面也可提供同源的 `catalogUrl`，请求一次安装。候选地址不接受凭据、查询参数或 fragment；网页只能请求状态或打开安装视图，不能确认来源、传入命令或授予权限。状态查询只返回需要确认的标志，不读取目录、不连接本机服务。

用户点击后，扩展自己的安装视图展示实际请求页面及目录地址。点击“继续，读取配置”后才检查 Chrome 站点权限并读取目录，目录的 `guide.url` 必须等于原请求页面，原文档必须仍然有效。读取后展示选中的能力名称、完整来源和站点范围；即使权限已授予，也必须再次点击“确认并安装本次配置”。之后复用浏览器与本机的安装协调器，提交前重新校验同一目录快照、选择身份及权限。

来源确认和安装授权保存在绑定扩展安装页的会话中，15 分钟后过期；取消会删除会话。来源变更、撤权、伪造页面或过期请求不能继续安装。一次安装不会写入长期信任目录，也不会授权该来源自动更新。未提供候选地址且未配置直接安装目录时，仍返回 `INSTALLATION_SITE_NOT_CONFIGURED`。

未设置该环境变量时，扩展使用默认安装站点的连接入口。更改构建配置后，需要重载或更新扩展。

### 环境管理入口

Preset 可通过 `defaults.management.setup` 声明安装器的 npm 包、版本或标签、HTTPS registry 和受支持的核心运行版本范围：

```json
{
  "management": {
    "setup": {
      "package": "@example/mearl-setup",
      "version": "beta",
      "registry": "https://registry.example.com/",
      "runtime": ">=3.0.0-beta.8 <4"
    }
  }
}
```

这里的 `management` 位于 `defaults` 中，随继承图和安装凭据保存。它是发行管理声明，不能通过用户 overrides 修改；切换声明使用显式 preset 选择。声明只描述 npm 参数，不接受 shell 命令、附加参数或执行钩子。

`mearl guide troubleshooting` 和扩展开发指南从本机已验证的安装凭据生成管理命令，不连接浏览器、检查更新或加载能力工厂。未选择 preset 时显示首次安装入口。已有选择但凭据缺失或损坏时，停止生成命令。

安装、更新和卸载共享本机生命周期租约。组件安装使用单独的租约，嵌套安装的子进程同时归属于两层租约。安装器在包命令执行前复查已接受的版本范围；卸载允许清理版本范围外的运行包，但仍要求安装记录可验证。原有 preset、Skill 和插件来源保护继续生效。
