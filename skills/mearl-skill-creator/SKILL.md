# Mearl Skill Creator

把网站操作沉淀为对 Agent 和人都可用的能力。同一 Skill 可通过 `app.command()` 提供 CLI、SDK 和 MCP 操作，也可按需导出 `toolbox` 提供 GUI；业务操作复用，界面草稿和预览由页面管理。

## 起点与执行环境

- 新建时，从 URL 和目标推导名称、参数、输出和实现形态。遵从指定目录；未指定时，从当前 Agent 的 Skill 配置或已发现路径确定标准目录，无法确定再询问，不猜仓库或父目录布局。
- 改造时先读完整 Skill、入口、相关 references 和测试，建立现有行为基线；保留有效能力和用户改动，不按模板重写。
- 通过已安装的 `mearl` Skill 操作浏览器。命令和参数按当前 `--help`；命令缺失或连接失败才排查环境，不为探索切换到另一套浏览器登录态。
- 认证、额外协议和外部 Provider 依据当前已安装能力及配套帮助选择。区分插件执行宿主身份、目标浏览器会话及本机/远端文件路径。

## 探索并验证契约

1. 缺少真实契约时，用 `tab_open` 打开或复用目标页面并保存 `tabId`，从 `page_snapshot` 和请求观察识别入口、认证与候选接口。已有代码、测试和文档能确认的内容不重复探索。
2. 读取、筛选和翻页由 Agent 执行。单动作通过 `diagnostics` 观察增量，跨动作使用 `tab_checkpoint` 与 `get_requests`；持续复用同一 Tab，不固化临时 `@ref` 或坐标。
3. 探索发布、审批、删除、支付等写入时，优先利用已有请求和提交前页面确认契约。“生成 Skill”不代表授权产生测试数据或真实写入；需要实际提交才能确认时，先说明具体目标和影响并取得授权。
4. 记录方法、URL、参数位置、分页、认证主体、成功/空结果/权限失败信号及必要回查。读取接口至少用最终选定的 Mearl 调用路径成功验证一次；未经验证的推断不能声明已支持。
5. 登录、验证码、扫码或硬件确认由用户在原页面完成，不索取凭据。Cookie、token、个人 ID 和一次性地址不进入生成文件；动态值由对应宿主的登录态或前置查询取得。

## 选择主路径

- **接口模式**：能脱离具体页面稳定重放的业务接口，优先使用；读取[接口型 Skill 设计](./references/api-skill-pattern.md)。
- **混合模式**：主要业务走接口，登录、一次性上下文或结果核对需要页面；只保留已证明不可省略的页面步骤。
- **页面模式**：操作依赖浏览器状态、Canvas、控件交互，或没有稳定接口；读取[页面型 Skill 设计](./references/page-skill-pattern.md)。

每项能力只交付一条验证过的主路径。接口失败不能用未说明的页面兜底掩盖；页面发现接口不代表最终认证也必须依赖页面。

## 生成 CLI 与 GUI

简单单动作可直接写 Mearl 命令；需要参数校验、分页、多接口或页面编排时，读取[Skill 插件规范](./references/cli-plugin.md)，提供 `scripts/main.mjs` 或 `scripts/main.py`。入口主要保留元信息、依赖组装与命令注册，复杂业务按职责拆到同目录模块，不为拆分而拆分。

- `SKILL.md` 说明触发边界、输入输出、调用入口、成功判定及登录/权限处理；参数从 input 获取。不要硬编码探索中的 Tab、临时 selector 或个人数据。
- 使用注入的 `app.invoke()` 和 `app.progress()`，不启动另一套浏览器控制进程；帮助与注册阶段不调用浏览器或业务接口。外部协议依赖通过已安装能力调用。
- 有 GUI 时导出 `toolbox`，按插件规范使用宿主主题和资源打包。页面面向人、CLI 面向 Agent；共享业务操作，表单草稿、选择和预览默认放浏览器内存。需要关闭界面后继续运行时使用持久任务或 `pageRuntime`，不用页面轮询维持后台工作。
- 工具箱先参考同类页面的字号、控件、间距和状态；分别验证 Popup 与独立页、浅色与深色截图，短表单默认一屏完成，主要操作保持可见。
- 写命令按已授权的调用执行，保留业务目标、危险环境、幂等和回查约束，不添加通用二次确认参数。结果不明确时先核验，不重复提交。
- 仅创建实际需要的入口、脚本、references 和 GUI 资源，不添加占位能力或备用实现。

## 验证与交付

1. 用 `npx @mearl/setup@3 plugin <实际 Skill 目录>` 注册脚本入口；确认帮助无副作用，位置参数与 JSON payload 进入同一业务逻辑。
2. 按项目现有测试布局验证参数、输出、错误和宿主选择；改造任务运行原有测试。若无项目测试位置，在临时目录验证，不把测试随 Skill 安装分发。
3. 用最终主路径验证只读结果；页面任务检查实际终态，GUI 检查两种尺寸和主题。涉及持久任务时验证关闭界面后继续、取消和导航隔离；大文件或高频流程检查累计传输与耗时。
4. 写入仅在已授权的合适目标执行并回查；未执行时明确说明验证范围。无法证明接口或页面业务终态时停止，不伪造成功。
5. 交付实际 Skill 路径、主路径、认证与执行宿主、CLI/GUI 用法、验证结果和仍需人工完成的步骤。
