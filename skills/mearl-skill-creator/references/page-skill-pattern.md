# 页面型 Mearl Skill 设计

仅在目标能力采用页面模式或混合模式时读取。页面模式不是接口发现失败后的无条件退路；生成结果必须说明页面步骤为何不可省略，并验证其稳定定位和终态信号。

## 流程表达

- 用目标和决策条件描述流程，例如“找到搜索框并输入关键词，提交后等待结果列表”，不要固化本次探索的事件序列、延时和坐标。
- 首次进入、导航完成或 DOM 大幅变化后用 `page_snapshot` 建立新状态。交互优先使用当次快照的语义 `@ref`、稳定可见文本或经过验证的稳定 selector。
- `@ref` 只在产生它的当前页面状态中使用，不能写进生成文件。坐标只适合 Canvas、拖拽或缺少 DOM 语义的目标，并应在运行时从截图或页面状态重新确定。
- 同一任务持续复用明确的 `tabId`。不要为了继续同一流程重复打开页面；只在原 Tab 失效、流程明确要求新页面或动作返回 `openedTabs` 时切换。
- 页面分支应根据可观察状态决定，例如按钮是否存在、URL、标题、提示文案或表单状态，不用固定等待时间猜测页面已经完成。

## 动作与观察

1. 页面操作使用 `page_click`、`page_type`、`page_scroll`、`page_hover`、`page_press`、`page_upload`、`page_drag` 和 `page_navigate` 等 Mearl action。
2. 紧密连续且中间无需判断的动作可以用 `run_actions`；需要根据每一步结果选择下一步时逐步执行。
3. `page_eval` 默认只用于一次性读取结构化状态或定位候选。只有没有对应页面 action、且风险可控时才修改页面；不得用它伪造点击、上传或业务成功状态。
4. 页面动作返回的 `action.success` 只证明动作已派发。还要结合 DOM/导航变化、页面提示、结果列表、详情状态或后续查询验证业务终态。
5. 视觉内容、Canvas、跨域 iframe 或纯视觉变化使用截图验证。普通 DOM 流程不要在每一步固定截图或完整快照。

覆盖层、持续采集或随网页交互更新的功能，使用 [Skill 插件规范](./cli-plugin.md) 中的 `pageRuntime` 与 `app.page()` 建立文档实例，页面事件交给 `app.runtimeCommand()` 后台处理。不要靠工具箱定时器维持功能，也不要在每次状态刷新时用 `page_eval` 重装监听器；界面通过实例事件订阅更新，持久状态由宿主管理。需调用本机 Codex 时使用模型任务，异步结果应用到 DOM 前检查原文档和取消信号。

## 可复用性

- 把用户输入、环境、页面入口和可变内容参数化。稳定的域名、路由模式、表单标签和成功文案可以记录为页面契约。
- 对重复文本提供作用域或附近语义，不使用 `nth-child`、构建产物类名、随机 ID 等脆弱 selector，除非已经证明它是目标网站的稳定契约。
- 对弹窗、新 Tab、iframe、懒加载列表和分页写清进入与退出条件。页面出现未识别状态时停止并返回当前 URL、标题和最小快照摘要，不盲目继续点击。
- 登录、验证码、扫码、硬件确认和人工审批是显式人工边界。Skill 应暂停并说明用户需要完成的动作，随后从同一 Tab 的可观察状态继续。

## 写操作与验证

页面写命令在调用后继续完成提交，不内置通用二次确认步骤：

1. 填写和提交前校验目标、环境、内容以及页面当前状态；缺少业务必填信息时停止。
2. 提交动作只执行一次。若动作后状态不明确，不要再次点击提交；先检查页面提示、按钮状态、网络诊断和查询结果。
3. 最终成功信号必须在探索时真实观察过，并写入生成 Skill。只有“弹窗关闭”“发生导航”或“按钮可点击”不足以证明业务完成。
4. 若页面流程同时产生稳定、可重放的业务接口，重新评估接口或混合模式；不要因为页面探索先完成就默认固化 UI 流程。
