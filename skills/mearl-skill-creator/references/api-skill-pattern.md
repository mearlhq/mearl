# 接口型 Mearl Skill 设计

仅在目标能力采用接口模式或混合模式时读取。这里规定生成结果的实现取舍，不替代从目标网站取得并验证真实契约。

## 选择入口形态

- 单个只读 HTTP 接口、参数简单且响应无需整理时，可以直接给出一条 `mearl send_request` 调用。
- 需要分页、多接口编排、字段归一化、HTML 解析、运行时前置查询、文件处理、重试或写入时，提供一个 Mearl Skill 插件入口，遵循 [Skill 插件规范](./cli-plugin.md)。
- 同一能力不要同时提供“直接命令”和“脚本”两条等价主路径。辅助排障命令可以单独说明，但不能绕过入口脚本的校验和安全约束。

脚本只负责已经验证的稳定工作。多个独立业务动作应使用明确的子命令或拆成少量职责清晰的脚本；不要制作一个靠大量隐式分支猜用户意图的万能脚本。

## 请求实现

1. 通过注入的 `app` 调用 Mearl，使用 async/await 编排请求。复用宿主客户端和浏览器上下文，不在插件内启动 mearl 子进程或导入全局 SDK。
2. 依赖浏览器会话的 HTTP/document 请求使用 `app.invoke('send_request')`；其他认证或协议按当前已安装能力及其配套 Skill 的真实契约选择，不假定特定身份插件存在。凭据由对应能力管理，不固化到代码。
3. 保留服务端要求的方法、Content-Type 和参数位置，不在 GET、JSON、表单之间试探。浏览器文件上传使用 `send_request.files`；`filePath` 是浏览器 Native Host 上的绝对路径，无法引用时传 Base64 内容与 `filename`。其他插件的文件路径按其执行宿主契约处理，不能把本机与远端浏览器路径混用。
4. 对列表能力明确分页字段、默认页大小、最大抓取范围、排序和停止条件。若声称“全部”，必须实际遍历全部分页。
5. 只做有证据支持的自动重试。网络瞬断、429 或 5xx 可有限重试；业务拒绝、参数错误和权限不足不得原样重复提交。

## 输入、输出与错误

- 从 handler 的 input 对象接收业务输入，检查必填值、互斥项、枚举和危险环境；不要根据 ID 长度、展示文案或历史样例猜业务类型。
- handler 返回稳定、最小的结构化结果或文本，宿主负责 stdout、--output 和退出码；进度写 stderr，失败抛 Error。完整响应只在确有用途的显式选项下返回。
- 区分 HTTP 成功、协议成功和业务成功。只有响应中的业务成功信号和必要回查都满足时才报告完成。
- 登录失效、域名权限不足、页面返回 HTML、限流和业务拒绝应有可区分的安全诊断。不要打印 Cookie、Authorization、token 或未经裁剪的敏感正文。

## 写操作

写命令由用户调用时直接执行，不增加通用二次确认门槛：

1. 提交前校验目标、环境、内容和必要的并发版本字段；缺少业务必填信息时停止。
2. 提交前查询当前状态，已完成、已关闭或不满足前置条件时停止，避免重复写入。
3. 提交后使用已验证的查询接口或返回标识回查。接口返回 200 或 `success: true` 但业务状态未改变时，不报告完成，也不自动重复提交。
4. 删除、支付、审批、发布等不同风险动作分别描述边界，不用宽泛的“处理”“修复”授权替代具体操作意图。

## 登录与页面前置

接口模式允许在确有需要时打开登录页或取得运行时上下文，但页面不是默认的数据读取通道。登录完成后回到接口主路径。若脚本临时打开页面，应复用明确的 `tabId`，且只在不会破坏用户所需终态时关闭自己新建的临时 Tab。
