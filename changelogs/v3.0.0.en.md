### Highlights

Mearl 3.0 connects browser automation, request debugging, and environment simulation to the browser extension, CLI, TypeScript SDK, and MCP. Agents can reuse browser sign-in sessions, with shared browser actions across the extension, CDP, and Providers.

### Features

- Install Profiles, integrations, Skills, and Providers together with defaults through a Preset. Setup verifies individual components, preserves user overrides, installs missing components, and resumes interrupted upgrades from saved resources.
- Complete local setup without a connected extension. Connected extensions can synchronize the same Preset; after connecting later, run `npx @mearl/setup preset repair` to synchronize it.
- Download and extract the extension with `npx @mearl/setup extension --extract`. The command prints a directory to load manually in Chrome developer mode; downloading and extracting require no remote debugging connection.
- Chat with Codex or Qoder in the toolbar popup or Agent side panel, and install missing local Agent components from the chat interface. Codex conversations can preview referenced HTML charts. Qoder cloud pairing is provided separately by the optional `@mearl/plugin-qoder` capability.
- Preview supported fixed devices with a centered phone frame and open the debugging panel beside or below the device. Page actions and screenshots target the business WebView. Frame availability depends on the selected device and App profile.
- Add App Profiles from the emulation menu or with `npx @mearl/setup profile install <source>`. One source can provide several Profiles. Installing it preserves the current Preset.
- Compose browser actions and registered Skill commands in JavaScript with `mearl run`, including top-level `await`, conditions, and loops. Scripts run in separate processes with cancellation, execution deadlines, and output limits.
- Run native WeChat mini-program projects and compiled `mp-weixin` output with the `wechat-miniprogram` Skill. Reuse browser page actions and device simulation; configure request mocks through `wxa.setup.js` or the runner's test API. Requests use Node forwarding and do not automatically share browser Cookies or request rules. See the [mini-program guide](https://github.com/mearlhq/profile-wechat/blob/main/docs/wechat-miniprogram.md) for compiler and file-access requirements.

### Changes

- Usage guides ship with the CLI. Run `mearl guide` for the core workflow or `mearl guide --list` to find a topic.
- Use Profiles for App emulation and integrations and Skills for protocol handlers and toolbox features. Check each plugin's help when updating SDK or MCP scripts that use protocol-specific actions.
- Skills can be installed and registered together with `npx @mearl/setup plugin install <source> --skill <name>`. The repository includes tools for design overlays, bilingual reading, format conversion, notes, tab management, and image compression.

### Upgrading and compatibility

- Core runtime packages require Node.js 20.18.0 or later; independent Providers declare their own requirements. The extension requires Chrome 120 or later, with higher requirements for some features. See [browser compatibility](https://github.com/mearlhq/mearl/blob/v3.0.0/packages/extension/README.en.md#browser-compatibility).
- Update the extension and local components together, and register Native Messaging through setup. The host names are `ai.mearl.skills` and `ai.mearl.mcp`. After installation, run `mearl check --local`, or `mearl check --cdp` for extension-free CDP connections.
- Providers use protocol version 3. Update the Provider SDK, rebuild bundled adapters, and restart Provider processes together with the Mearl host.
- Qoder cloud pairing reads macOS Keychain PATs from the `ai.mearl.qoder.pat` service. Reconfigure credentials stored under another service name, or provide the PAT through an environment variable or environment file.
