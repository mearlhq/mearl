# Mearl 扩展界面设计

适用于工具栏 Popup、独立扩展页及其中的对话框。

## 选同类界面作参照

| 要决定的事 | 现有参照 |
| --- | --- |
| 设置卡片的密度和对齐 | 设置页的「Agent 服务」及相邻卡片。比较外边缘、水平内边距、标题和说明的位置。 |
| 设置表单的控件尺寸 | 「外部服务」使用的[默认按钮](src/pages/options/components/Button.tsx)。同行的输入框和提交按钮沿用它的字号和高度，随设置字号一起伸缩。 |
| 对话框的边界和操作区 | 嵌入式对话框使用现有 [Modal](src/pages/panel/components/modal/Modal.tsx)。独立授权窗口使用整个可用视口，正文可滚动，底部操作区保持可见。 |
| 颜色、边框和暗色主题 | [全局语义变量](src/global.css)。沿用同一用途的背景、文字、边框和选中态。 |

局部改动优先参考同一宿主里解决相似任务的界面。相邻卡片沿用相同的边线和视觉节奏，高度随内容调整。宽版可以横向排列信息和操作，窄版优先保留输入空间。改变字号或语言后，标题和动作仍应清楚可辨。

## 操作和反馈

- 按用户意图组织操作。Preset 表单用同一个动作提交当前来源，根据状态显示「安装」或「更新」。确认页展示本次来源和所需授权。
- 状态取自实际结果。区分读取中、尚未配置、读取失败、浏览器部分已就绪和本机组件待安装。可恢复的失败提供明确的重试动作，保留用户已填的内容。
- 检查键盘路径。焦点清楚可见，Enter 提交当前表单，关闭对话框后焦点返回触发它的控件。

## 在实际界面里审阅

1. 动手前打开实际界面，找到最相近的参照，明确用户要完成的事和这次要改善的地方。
2. 把改动区域和参照放在同一画面，走一遍用户最常用的路径。检查下一步是否明显、状态是否准确，再比较层级、密度和对齐。发现偏差先自行修正。
3. 复看受影响的窗口尺寸、主题和相关状态。截图和临时测量用于审阅布局。回归测试覆盖会影响用户操作的行为，例如安装成功却显示失败、换了来源仍提交旧值。

需要人来决策时，给出推荐方案和具体取舍。能沿用现有约定解决的细节先做完。

## 何时记录人工反馈

先用反馈改好当前界面。只有反馈确认了以后还会用到的设计判断，且现有指引或组件表达得不够清楚，才更新最相关的一条。记录适用情境和可复用的判断，例如「同类控件跟随同一套尺寸」，具体数值由实际组件提供。已覆盖的发现和一次性的微调留在当前任务里。
