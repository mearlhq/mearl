# Qoder Cloud Agent pairing

[简体中文](cloud-pairing.md) | [English](cloud-pairing.en.md)

Use this mode when running in Qoder Cloud Agent. Other remote agents use cloud-server / WebSocket. Install the Qoder capability on the browser machine as described in this package's README. The Agent machine can generate pairing information directly with this package. Both modes share Mearl action contracts.

Qoder mode uses official Client-Side custom tools and Session event APIs, without Cloudflare Tunnel or treating Qoder sandbox public endpoints as WebSockets. Follow this sequence:

1. Check whether the Agent already exposes a Client-Side custom tool named `mearl`. If so, run:

   ```bash
   npx @mearl/plugin-qoder pair
   ```

   Read the local `npx @mearl/cloud-connector start "qoder://pair/..."` command and `pair` input from output. Show the local command to the user, then immediately submit the generated `pair` input to the `mearl` custom tool. It pauses until the user runs the connection command on the browser machine and pairing completes.

2. After pairing, do not run `mearl ...` shell commands inside the Qoder sandbox for this Session's browser operations. Internally map the Skill's action, payload, browser, and timeout to custom-tool calls. Deliver ordinary Mearl results to users without exposing transport differences.

3. Without a `mearl` tool, first determine whether available Qoder PAT and Agent ID/version permit reading the complete existing `tools` array, appending the configuration below, and updating the Agent. Do not overwrite other tools. If permissions or information are missing, guide the user to add:

   ```json
   {
     "type": "custom",
     "name": "mearl",
     "description": "Invoke a Mearl browser action on the user's paired local browser. Use action=pair only with a code generated by @mearl/plugin-qoder pair.",
     "input_schema": {
       "type": "object",
       "additionalProperties": false,
       "properties": {
         "action": { "type": "string" },
         "payload": { "type": "object" },
         "browser": { "type": "string" },
         "timeoutSec": { "type": "number", "minimum": 1 }
       },
       "required": ["action"]
     }
   }
   ```

   Tool configuration belongs to the Agent and affects new Sessions only. Tell users to create a new Session and restart the normal flow rather than repeatedly retrying the current Session.

4. Only if the local connector reports missing authentication, 401, or an expired PAT, follow its error to configure a Qoder PAT on the browser machine and restart. Errors provide supported credential sources and configuration. Do not ask users to send PATs to the Agent or put them in command URLs, chat, or logs. If users proactively provide a PAT and explicitly request configuration, write a supported source without repeating it.

5. `page_screenshot` prefers Qoder image-content blocks while preserving metadata. If the API version rejects image blocks, connector falls back to JSON text containing original base64 so image data is not lost.
